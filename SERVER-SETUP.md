# Сервер ГИРЯ: этап 2

Реализованы сервер Node.js 24.14.0, SQLite, миграция схемы, SMTP-вход по шестизначному коду, сессии, CSRF и окно аккаунта. Сервер раздаёт `dist/` и `/api/v1` с одного origin. Это исходники готового к настройке сервера; само наличие файлов не означает, что облачный экземпляр уже запущен.

Синхронизация тренировок, перенос гостевых записей в аккаунт, разделы IndexedDB для аккаунтов и удаление аккаунта относятся к следующему этапу. Сейчас база хранит аккаунты и сессии, а тренировки остаются в гостевом IndexedDB. Подготовлены таблицы упражнений, программ, тренировок, подходов и замеров с составными внешними ключами по владельцу, но API записи тренировок не открыт. Пользователь видит это ограничение в окне входа.

## Локальный запуск

1. Установить Node.js из `.node-version`, выполнить `npm ci`.
2. Скопировать `.env.example` в `.env`. Создать два независимых случайных секрета по 32 байта командой из примера. Не публиковать `.env`.
3. Оставить `APP_ORIGIN=http://localhost:3000`, `DATABASE_PATH=./data/girya.sqlite`.
4. Для реальных писем настроить SMTP. Без него доступен гостевой дневник, а форма объясняет, что вход ещё не подключён. Readiness вернёт 503; production без SMTP не стартует.
5. Выполнить `npm run migrate`, `npm run test:ci`, `npm run build`, `npm start`.
6. Открыть http://localhost:3000. При изменении порта изменить также APP_ORIGIN.

## Почта

Нужен подтверждённый отправитель и SMTP-сервис. Его пароль/ключ вводится в секреты хостинга, а не в GitHub или чат. Переменные: SMTP_HOST, SMTP_PORT, SMTP_SECURE, SMTP_USER, SMTP_PASS, SMTP_FROM. Обычно 465 использует SMTP_SECURE=true; 587 — false с обязательным STARTTLS. Проверка сертификатов включена. Сервер проверяет подключение при старте, а отказ отправки возвращает 503 и не выдаёт код клиенту. Принятие письма SMTP-сервером не гарантирует доставку во входящие: отдельно проверить SPF/DKIM/DMARC, спам и реальный тестовый адрес.

Для отдельного локального Mailpit можно использовать SMTP_HOST=127.0.0.1, SMTP_PORT=1025, SMTP_SECURE=false, SMTP_LOCAL_TEST=true, SMTP_FROM=login@example.test. Такой режим допускается только на loopback и запрещён в production. Коды не показываются в интерфейсе приложения, API, логах или файлах БД в открытом виде. Тесты используют отдельный синтетический почтовый ящик в памяти.

## Облако / Amvera

Dockerfile и amvera.yml подготовлены; Docker-сборка в текущем окружении не проверялась (Docker не установлен). Перед выкладкой проверить образ в CI/на хостинге. Один экземпляр, порт 3000, постоянный диск /data, DATABASE_PATH=/data/girya.sqlite. Том должен быть доступен на запись UID 1000. Не запускать несколько реплик SQLite.

Установить NODE_ENV=production, APP_ORIGIN=https://точный-домен-приложения, два секрета и все SMTP-переменные. APP_ORIGIN — без пути и завершающего слеша. В ТЗ этим настройкам соответствуют APP_BASE_URL и DB_PATH; в реализации они названы APP_ORIGIN и DATABASE_PATH. SESSION_SECRET подписывает CSRF-токены; LOGIN_CODE_SECRET защищает коды и ключи лимитов. Сессионные токены хранятся только как SHA-256, случайные значения генерируются криптографически.

TRUST_PROXY=0 по умолчанию. Включать 1 только если входящий прокси ПЕРЕЗАПИСЫВАЕТ X-Forwarded-For адресом клиента и сервер недоступен в обход него. Иначе IP-лимит обходится или применяется ко всем пользователям как к одному IP. За неподтверждённым прокси оставить 0; email-лимиты продолжают работать.

Проверка процесса: /api/v1/health/live. Готовность БД/настроек: /api/v1/health/ready. Тело не содержит адресов, паролей или путей БД. HTTP API всегда no-store; service worker исключает /api/. Нет CORS-доступа с GitHub Pages. Старый сайт продолжает работать локально, серверный адрес отдельный. Новый адрес не читает старый IndexedDB: перенос через экспорт предусмотрен последующим этапом.

До открытия реальным пользователям: развернуть тестовую среду с отдельной БД и почтой, проверить письмо на двух адресах, вход, выход со всех устройств и HTTPS-cookie. Добавить политику обработки email и согласованный срок хранения аккаунтов. Платные сервисы/тарифы не созданы.

## Резервная копия, обновление и откат

`npm run backup:db -- /абсолютный/закрытый/путь/backup.sqlite` использует SQLite online backup. Это не копирование активного файла без WAL. Копия содержит email и сессии; хранить вне dist, шифровать, не публиковать. Планировщик часовых копий, внешнее хранилище и срок хранения ещё нужно настроить на выбранном хостинге.

Перед обновлением: backup, остановка старого экземпляра, проверка тестов, миграция одним процессом, запуск, readiness и реальный вход. В схеме v1 повторная миграция безопасна. Откат: остановить сервер, сохранить неисправную БД отдельно, проверить резервную копию через PRAGMA integrity_check на закрытой машине, восстановить БД на том же диске и соответствующую версию образа. Не восстанавливать поверх работающего процесса. Протестировать процедуру на тестовой среде до production; RPO/RTO ещё не подтверждены.

## Поведение входа

Email сравнивается без учёта регистра, домен IDN нормализуется; точки и +suffix сохраняются. Код живёт 10 минут, максимум 5 неверных проверок. Новый доставленный код отменяет прежний; неуспешная SMTP-попытка прежний не отменяет. Отправка: 60 секунд между запросами, 5/час на email, 30/час на IP. Проверка: дополнительно 60/час на IP. Ограничения хранятся в БД и переживают перезапуск. Неактивные challenge очищаются после суток; неактивные счётчики после суток.

Сессия: 30 дней максимум, 14 дней без активности, случайный токен 256 бит. Cookie __Host-girya_session, HttpOnly, Secure, SameSite=Lax, Path=/; локально отдельное dev-имя без Secure. Меняющие запросы требуют точного Origin и подписанного double-submit CSRF-токена из /auth/csrf. POST logout-all отзывает все сессии. Повторный вход в том же браузере отзывает прежнюю сессию этого браузера.

Контракт текущего этапа: server/openapi.json. Полный контракт синхронизации появится до реализации её API. Никакие неизвестные маршруты не возвращают данные другого пользователя; /me определяет владельца исключительно по сессии.

Источники настроек: [SMTP Nodemailer](https://nodemailer.com/smtp), [Amvera Docker](https://docs.amvera.ru/applications/configuration/docker.html), [SQLite Node.js](https://nodejs.org/api/sqlite.html).
